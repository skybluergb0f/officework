# 수변전 일지 Ubuntu 웹서비스 설계

## 목표

현재 단독 HTML 입력 화면을 Ubuntu에서 제공하는 웹서비스로 전환한다. Windows 사용자는 브라우저로 접속해 본관 수변전 일지를 입력하고, 원본 엑셀 저장 완료 후 브라우저 인쇄를 실행한다. 수기 양식 인쇄는 엑셀 저장과 분리해 계속 제공한다.

## 확인된 환경과 제약

- 서버: Ubuntu 24.04 LTS, Node.js 22, Python 3.12 사용 가능. FastAPI와 openpyxl 사용 가능
- Nginx가 실행 중이며 LibreOffice는 설치되어 있지 않음
- 현재 로컬 브리지는 Windows Excel COM에 의존하므로 Ubuntu 웹서비스에서 사용하지 않음
- GitHub 대상 `skybluergb0f/officework`는 공개 저장소임
- 실제 원본 엑셀은 운영 데이터로 취급하며 공개 GitHub에는 절대 포함하지 않음

## 제안 구조

- FastAPI 웹서비스가 기존 HTML 입력 화면과 JSON API를 같은 출처(origin)로 제공한다. SQLite는 서버 로컬 디스크에 `data/substation-log.sqlite3`로 둔다.
- SQLite에는 JSON 덩어리 대신 일지 헤더, 시각별 계측값, 계량기 검침값, 월마감값, 시각 수정 상태를 정규화해 저장한다. 각 UI의 `data-path`는 안정적인 `group_key`/`field_key` 조합에 일대일 연결한다. 숫자 입력은 숫자 열로 저장하고 빈 값은 `NULL`로 둔다.
- 기존 날짜별 입력 UI를 유지한다. 화면을 열면 SQLite에서 날짜별 기록을 불러오며, 해당 날짜가 아직 SQLite에 없을 때는 설정된 원본 월별 엑셀에서 읽어 SQLite에 초기 적재한다.
- 원본 엑셀은 시놀로지 NFS 마운트 경로의 월별 파일을 사용한다. 기본 운영 위치는 `/home/nuri/ftp_hdd/syn_nuri_work/02. 일지/[01 매일] 본관 - 수변전 일지/{year}년`이며, 실제 경로와 파일명 패턴은 환경 설정으로 지정한다. SQLite 파일은 NFS가 아닌 서버 로컬 `data/`에 둔다.
- 저장·인쇄 버튼은 다음처럼 구분한다.
  - `수기 양식 인쇄`: 현재 입력 화면만 인쇄하고 원본 파일은 변경하지 않는다.
  - `저장`: 선택 기록의 각 필드를 SQLite에 트랜잭션으로 저장한다.
  - `원본 엑셀 저장 후 인쇄`: SQLite 저장 후 동기화 대기(outbox) 상태를 만들고, 해당 필드들을 원본 엑셀 대응 셀에 반영한다. 두 저장이 모두 성공한 뒤에만 인쇄한다. 엑셀 동기화가 실패해도 SQLite의 입력은 보존하고 재시도 상태를 보여주며 인쇄는 시작하지 않는다.
- 같은 날짜에 대한 변경은 직렬화한다. 엑셀 파일 쓰기 전 백업을 만들고 임시 파일 저장 및 재열기 검증 후 원본 경로로 교체한다. 앱 재시작 시 미완료 엑셀 동기화를 재시도한다.
- 프록시 뒤에서만 접근하도록 FastAPI는 `127.0.0.1:18790`에 바인딩한다. 기존 HTTPS Nginx 도메인의 `/substation-log/`에서 인증을 거쳐 제공한다.
- GitHub에는 애플리케이션 소스, 예시 환경설정, 배포 문서만 올린다. `.xlsx`, SQLite 데이터베이스, 실제 `.env`, 백업 파일은 `.gitignore` 대상이다.

## 엑셀 저장 범위

선택 날짜의 `DD일` 시트와 월 요약 시트에 SQLite의 필드 값을 대응 셀로 기록한다. 월별 원본에는 인쇄 설정 파트가 있으므로 엑셀 쓰기는 ZIP 패키지 안에서 대상 셀 값만 갱신하고, 수식·서식·인쇄 영역·printerSettings 및 변경 대상이 아닌 모든 패키지 파트를 보존한다. 필드 매핑에는 변압기, VCB, 냉동기, 저압·정류기반·축전지(축전지 A 포함), 계량기 검침·월 마감, 작업자와 특이사항을 포함한다. 일일 계량기 9·10은 원본 일일 검침표에 대응 셀이 없어 SQLite에는 저장하고 엑셀에 투영하지 않는다는 사실을 사용자에게 표시한다. UI 필드 키에서 SQLite 레코드/필드, 엑셀 시트/셀까지 추적 가능한 매핑을 유지한다.

9월 자료 가져오기와 테스트는 시놀로지 원본이 아니라 프로젝트 `data/` 폴더의 엑셀 복사본에서만 수행한다. 수식 셀은 엑셀에 저장된 계산 캐시값을 읽는다. 숫자 필드에 잘못된 텍스트가 있으면 수치 값은 `NULL`로 두고 원문을 별도 `source_text` 열에 보존하며 자동으로 수정하지 않는다. 2026년 9월 복사본의 `2026-09-14`, 14:00, 변압기 냉난방 셀 `BA22`에는 `45..9`가 있어 이 원문을 보존한다.

## 데이터 보호와 오류 처리

- 인증되지 않은 요청은 엑셀 API에 접근할 수 없다.
- 저장 실패 시 UI에 실패 상태를 표시하고 인쇄를 시작하지 않는다.
- 동시 저장 요청은 파일 단위로 잠금/직렬 처리한다.
- SQLite 트랜잭션과 `workbook_sync` outbox 상태를 사용해 앱 데이터와 엑셀 간 동기화 누락을 재시도 가능하게 만든다.
- 데이터베이스 백업과 엑셀 백업은 각각 Git 추적 밖에 둔다.
- 로그에는 인증정보와 입력된 계측값을 남기지 않는다.
- 원본 파일은 시놀로지 NFS의 일지 폴더에서 읽고 쓰며, 공개 웹 경로에 파일 다운로드 경로를 만들지 않는다. SQLite와 백업은 서버 로컬 비공개 `data/`에 둔다.

## 배포 및 검토 흐름

1. 구현 계획에 따라 SQLite 스키마, 필드 매핑, API, UI, 배포를 구현한다.
2. 실제 NAS 원본 파일은 읽기 전용 점검과 임시 복사본 검증을 먼저 마친 다음 운영 저장 경로로 사용한다.
3. 앱 소스와 배포 설정을 공개 저장소 `skybluergb0f/officework`에 푸시한다. 실제 엑셀, SQLite DB, 백업, 운영 비밀정보는 푸시하지 않는다.
4. Nginx HTTPS 및 인증 경로를 확인한 후에만 Windows 브라우저 접속을 개방한다.

## 완료 조건

- Windows 브라우저에서 같은 서비스에 접속해 날짜별 기록을 읽고 저장할 수 있다.
- 입력한 각 UI 필드가 SQLite의 명시된 레코드/필드 조합에 저장되고 재조회된다.
- 저장 후 인쇄와 저장하지 않는 수기 인쇄가 별도 동작한다.
- 원본 엑셀 저장 성공 시 SQLite와 대응 셀이 일치하고, 저장 오류·동시 요청에도 DB/원본 파일의 일관성과 복구 가능성이 유지된다.
- 복사본 대조에서 기존 엑셀 서식 및 수식이 보존된다.
- 인증과 HTTPS를 거치지 않는 외부 접근은 허용되지 않는다.
- 공개 저장소에 원본 엑셀, 백업, 자격증명, 사내 접속 비밀정보가 없다.
