# 수변전 일지 Ubuntu 웹서비스 설계

## 목표

현재 단독 HTML 입력 화면을 Ubuntu에서 제공하는 웹서비스로 전환한다. Windows 사용자는 브라우저로 접속해 본관 수변전 일지를 입력하고, 원본 엑셀 저장 완료 후 브라우저 인쇄를 실행한다. 수기 양식 인쇄는 엑셀 저장과 분리해 계속 제공한다.

## 확인된 환경과 제약

- 서버: Ubuntu 24.04 LTS, Node.js 22, npm, Python 3.12 사용 가능
- Nginx가 실행 중이며 LibreOffice는 설치되어 있지 않음
- 현재 로컬 브리지는 Windows Excel COM에 의존하므로 Ubuntu 웹서비스에서 사용하지 않음
- GitHub 대상 `skybluergb0f/officework`는 공개 저장소이며 비어 있음
- 실제 원본 엑셀은 운영 데이터로 취급하며 공개 GitHub에는 절대 포함하지 않음

## 제안 구조

- Node.js 웹서비스가 HTML, CSS, 브라우저 스크립트와 JSON API를 같은 출처(origin)에서 제공한다.
- 백엔드는 서버의 비공개 데이터 경로에 둔 원본 `.xlsx`를 읽고 쓴다. 파일 경로와 포트는 환경 설정으로 지정하고 소스 코드에 개인 경로를 하드코딩하지 않는다.
- 기존 날짜별 입력 UI를 유지한다. 날짜를 열 때 해당 일지 기록을 API에서 가져오며, 저장·인쇄 버튼은 다음처럼 구분한다.
  - `수기 양식 인쇄`: 현재 입력 화면만 인쇄하고 원본 파일은 변경하지 않는다.
  - `원본 엑셀 저장 후 인쇄`: 선택 날짜의 셀에 저장하고 성공 응답 뒤에만 브라우저 인쇄 대화상자를 연다.
- 저장은 한 번에 하나씩 직렬화한다. 저장 전 백업을 만들고 임시 파일 저장 및 검증 후 원본 경로로 교체해 중단 시 부분 파일이 남지 않도록 한다.
- 프록시 뒤에서만 접근하도록 Node 서비스는 루프백에 바인딩한다. Nginx 경유 HTTPS와 인증이 확인되기 전에는 외부 네트워크로 공개하지 않는다.
- GitHub에는 애플리케이션 소스, 예시 환경설정, 배포 문서만 올린다. `.xlsx`, 실제 `.env`, 백업 파일은 `.gitignore` 대상이다.

## 엑셀 저장 범위

선택 날짜의 `DD일` 시트와 월 요약 시트에 현재 입력 모델을 대응 셀로 기록한다. 저장 구현은 기존 원본의 시트·수식·서식·인쇄 영역을 유지하는지 복사본으로 확인한 뒤 확정한다. 기존 셀 매핑에는 변압기, VCB, 냉동기, 저압·정류기반·축전지(축전지 A 포함), 계량기 검침·월 마감, 작업자와 특이사항이 포함된다. 원본 셀이 없는 UI 항목은 무시하지 않고 저장 전에 사용자에게 명시한다.

## 데이터 보호와 오류 처리

- 인증되지 않은 요청은 엑셀 API에 접근할 수 없다.
- 저장 실패 시 UI에 실패 상태를 표시하고 인쇄를 시작하지 않는다.
- 동시 저장 요청은 파일 단위로 잠금/직렬 처리한다.
- 로그에는 인증정보와 입력된 계측값을 남기지 않는다.
- 원본 파일은 서버의 비공개 데이터 디렉터리에만 두고 공개 웹 경로에서 직접 다운로드할 수 없게 한다.

## 배포 및 검토 흐름

1. 이 설계를 검토하고 승인한다.
2. 승인된 설계로 구현 계획을 작성한다.
3. 원본 엑셀은 GitHub 밖에서 안전하게 서버에 배치하고, 복사본으로 셀 매핑과 저장·복구 동작을 확인한다.
4. 앱 소스와 배포 설정을 공개 저장소 `skybluergb0f/officework`에 푸시한다. 실제 엑셀과 운영 비밀정보는 푸시하지 않는다.
5. Nginx HTTPS 및 인증 경로를 확인한 후에만 Windows 브라우저 접속을 개방한다.

## 완료 조건

- Windows 브라우저에서 같은 서비스에 접속해 날짜별 기록을 읽고 저장할 수 있다.
- 저장 후 인쇄와 저장하지 않는 수기 인쇄가 별도 동작한다.
- 저장 오류·동시 요청에도 원본 엑셀 파일이 손상되지 않고, 복사본 대조에서 기존 서식 및 수식이 보존된다.
- 인증과 HTTPS를 거치지 않는 외부 접근은 허용되지 않는다.
- 공개 저장소에 원본 엑셀, 백업, 자격증명, 사내 접속 비밀정보가 없다.
